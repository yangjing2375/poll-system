## 二、动态数据

自动化脚本每次执行会生成新的数据，避免与历史数据冲突：

- 注册类用例使用 `user{timestamp}`（Postman）或 `u{uniqid}`（PHPUnit）作为用户名与邮箱前缀，保证用户名、邮箱唯一。
- 投票类用例登录全新用户，确保「同一用户对同一投票只能投一次」的校验不会因上一轮数据而误判。
- 创建投票用例使用带时间戳的标题，便于在管理端列表中定位本次生成的记录。

## 三、边界与异常数据

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 用户名/邮箱/密码为空 | `username="", email="", password=""` | 400 类业务提示，不写库 |
| 邮箱格式非法 | `email=abc`、`email=a@b` | 提示邮箱格式不正确 |
| 密码长度不足 | `password=123` | 提示密码长度至少 6 位 |
| 用户名重复 | `username=alice` | 提示用户名已存在 |
| 标题超长 | 300 字符标题 | 拒绝或按字段长度截断，不得 500 |
| 选项全部为空串 | `options=["", "  "]` | 提示至少两个有效选项 |
| 选项只有一个 | `options=["A"]` | 提示至少两个选项 |
| 最大可选数大于选项数 | `is_multiple=1, max_options=5, options=[A,B]` | 提示最大可选数不能超过选项数量 |
| 结束时间早于当前时间 | `end_time=2020-01-01` | 提示结束时间不能早于当前时间 |
| 单选投票提交多项 | `poll_id=1, option_ids=[1,2]` | 提示最多只能选择 1 项 |
| 多选超过上限 | `poll_id=2, option_ids=[4,5,6]` | 提示最多只能选择 2 项 |
| 重复选项 | `option_ids=[1,1]` | 去重后按 1 项计票 |
| 选项归属其他投票 | `poll_id=1, option_ids=[5]` | 提示选项不存在 |
| 投票 ID 非法 | `poll_id=0`、`-5`、`abc`、`9999` | 提示投票 ID 无效 / 投票不存在 |
| 已禁用/已结束投票 | `poll_id=3` | 提示已禁用 / 已结束，不写库 |
| 未登录访问 | 无 Cookie 请求投票与结果接口 | 提示请先登录 |
| 越权访问 | 普通用户访问 `/api/admin_polls.php` | 提示无权限访问 |
| 分页越界 | `page=-1`、`page=abc`、`limit=99999`、`limit=0` | 收敛为第 1 页 / 上限 100 / 下限 1，不返回 500 |
| 搜索注入 | `search=' OR 1=1 --` | 预处理生效，返回空结果而非全表 |
| 头像伪装 | 文本文件改名为 `1.jpg`，Content-Type 设为 `image/jpeg` | 按真实内容判定，拒绝上传 |

## 四、数据重置

需要恢复到初始状态时执行：

```bash
mysql -uroot -proot --default-character-set=utf8mb4 < sql/schema.sql
```

脚本使用 `CREATE DATABASE IF NOT EXISTS`、`CREATE TABLE IF NOT EXISTS` 与 `INSERT IGNORE`，重复执行不会破坏既有数据；如需完全重置，先 `DROP DATABASE poll_system;` 再导入。
